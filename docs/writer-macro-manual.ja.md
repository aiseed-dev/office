# writer マクロの手引き(Python)

*正本(primary)は英語版: [writer-macro-manual.md](writer-macro-manual.md)。この日本語版は副です。*

writer のマクロは、**開いている文書の複製**を檻(サンドボックス)の中で
python-docx を使って直す Python の台本です。成功すると直った複製が読み
戻され、**Ctrl+Z 一回**で丸ごと戻せます。失敗したら文書は無傷。文書に
実行コードが載ることはなく、**開いただけでは何も実行されません**。

## 動かし方

3通りあります:

1. **プラグインタブ > マクロ** — `.py` ファイルを選ぶ。台本には中身だけを
   書きます(下の約束事)。
2. **プラグインタブ > プラグインの管理** — `~/.config/office/plugins/` に
   置いた `.py` が一覧に出て、押すと同じ檻で走ります。
3. **AI タブ > マクロを書く** — 用件を伝えると、モデルが台本を書いて
   プラグイン置き場に置きます(`ai台本N.py`)。**自動では走りません** —
   読んで確かめてから、一覧から実行します。

## 台本の約束事

次のものは用意済みです — 台本に書かないでください:

```python
# 用意済み:                    書かない:
d          # 文書              import docx / docx.Document(...) / d.save(...)
```

- **`d`** は python-docx の `Document`(python-docx の API が全部使えます)。
- **`print()`** — 最後に印字した行がステータスバーに出ます。何をしたかを
  一行で報告して終わるのが行儀です。
- **できない・危うい頼みは `raise SystemExit("理由")` で断る。** 理由は
  利用者に見え、文書は無傷のままです。黙って空振りしない。

## 名前つき記入欄 — 様式の背骨

まず欄に名前を付けます: **フォームタブ**で記入欄を挿し、欄の中にカーソル
を置いて**「名前」釦**。名前は docx の `w:tag` に入るので、Word と往復
しても生きています。日本の様式は同じラベルが繰り返されるので(様式1 には
住所/商号が3組ある)、`代表・住所` `協力1・住所` のように**節つきの名前**
で区別します。

| 関数 | はたらき |
|---|---|
| `fill(名前, 値)` | その名前の欄**すべて**に書く(2枚目に同じ欄がある様式のため) |
| `fill_one(名前, 値)` | 最初の一つだけに書く |
| `extract(名前)` | 欄の値を読む |
| `fields()` | (名前, 値) の一覧 — 様式のデータ台帳 |

どれも**無い名前ははっきり断ります** — 打ち間違いが黙った空振りになる
ことはありません。

```python
fill("代表・商号", "日本フネン株式会社")
fill("担当・氏名", "山田太郎")
print("2カ所記入しました")
```

```python
# 回収した様式から吸い上げる(台帳化は calc / polars と組んで)
for name, value in fields():
    print(name, value)
```

**ラベルの文字を探して隣のセルに書く走査はしないでください** — 結合セルは
同じセルを二度返し、均等割付はラベルに空白を挟み、同名ラベルは別の相手に
誤爆します。そうしなくて済むように名前があります。

## 雛形 — 出して終わりの量産文書

通知書・契約書・送付状のような「作って送って終わり」の文書は、記入欄では
なく **`{{差し込み口}}` の雛形**で作ります。`{{顧客名}}` と writer や
Word で打つだけで、差し込みは docxtpl が引き受けます。

| 関数 | はたらき |
|---|---|
| `render(辞書)` | 雛形に辞書を差し込む。結果がそのまま保存される |
| `tpl_fields()` | 差し込み口の名前一覧 — 雛形の仕様書 |

```python
render({
    "顧客名": "青森県庁",
    "担当者": "山田",
    "明細": [{"品名": "防火戸", "数量": 3}, {"品名": "枠", "数量": 6}],
})
print("差し込みました")
```

明細のくり返しは `{%tr %}`。**この印は1つで表の1行を丸ごと使います** —
合計3行の形が正です:

| 品名 | 数量 |
|---|---|
| `{%tr for m in 明細 %}` | |
| `{{m.品名}}` | `{{m.数量}}` |
| `{%tr endfor %}` | |

実際に雛形を壊すのは次の2つです(編集で `{{ }}` が中で割れるのは大抵
無害 — docxtpl が自力で繋ぎ、writer も開くときに繋ぎます):

- `{%tr %}` を明細と同じ行に書く(専用の行に置く)
- IME の**全角の `{{ }}`**(半角で打つ)

## python-docx を直接使う

`d.paragraphs`・`d.tables`・`d.sections` など python-docx の全部が使えます。
実測にもとづく作法が2つ:

- **表は行でなめる。** `tb.cell(i, j)` は呼ぶたびに結合の格子を組み直し
  ます — 1,920 セルの罫線帳票で、下の形なら **91ms**、`cell(i, j)` の
  ループだと **12.7秒**でした:

  ```python
  for tb in d.tables:
      for row in tb.rows:
          for c in row.cells:
              ...
  ```

- **書式を保って差し替える。** `c.text = "…"` は run の書式を潰します。
  最初の run に書くのが安全です:

  ```python
  p = cell.paragraphs[0]
  if p.runs:
      p.runs[0].text = "山田太郎"
      for r in p.runs[1:]:
          r.text = ""
  else:
      p.add_run("山田太郎")
  ```

## 檻(サンドボックス)

マクロは bubblewrap の檻で走ります: **ネットは無し**、**ホームは空に
見え**、書けるのはマクロの作業場だけ。`.venv` のライブラリ(python-docx /
docxtpl / polars …)は使えます。実際の帰結:

- `~/名簿.csv` は読めません。データは台本に直に書くか、`render()` の
  辞書で渡すか、文書自身から取ります。
- 台帳を回す大量差し込みは **calc の Python**(ブックが束縛される)の
  受け持ちです — writer のマクロは開いている1文書を直す道具です。

## AI に書かせる

**AI タブ > マクロを書く**は、この手引きの作法(上の関数だけを使う・
行でなめる・print で報告・SystemExit で断る)と、**開いている文書の
記入欄の名前一覧**をモデルに渡します。答えはプラグイン置き場に置かれて
一覧に出るだけ。**読んでから実行** — これが安全の仕組みの全部で、VBA の
移し替えと同じ規律です(機械が書き、人が読み、檻が走らせる)。

## 困ったとき

| 表示 | 意味 |
|---|---|
| `python-docx がありません` | `pip install python-docx`(.venv があればそちらへ) |
| `docxtpl がありません` | `pip install docxtpl` — `render`/`tpl_fields` のときだけ要る |
| `記入欄「X」が見つかりません` | X という名前の欄が無い — フォームタブ「名前」で付けるか、`fields()` で確かめる |
| `雛形が壊れています: …` | 雛形の書き方 — `{%tr %}` の行の置き方と全角の `{{ }}` を確かめる |
| `マクロ: <エラーの最後の行>` | 台本が例外で止まった — 文書は変わっていません |
