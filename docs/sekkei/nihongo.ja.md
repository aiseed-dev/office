# SEKKEI — 日本語

設計の正本の一部(なぜ作るか・校正・辞書・K4(縦書き/ルビ/均等割付)・右横書き)。2026-08-08 に SEKKEI.md から部屋割りで
**純移動**した(文言は変えていない)。書き込みの規則は SEKKEI.md の頭を見よ。

## 校正 — ローカルの Command A+(`ui/src/proof.rs`)

日本語の「スペルチェック」は綴りの話ではない。実際に起きるのは**誤変換**(以外/意外)・
**表記ゆれ**(問合せ/問い合わせ)・送り仮名・重複表現で、辞書式では検出できない。
だから中身にモデルを使う。**これは「AI機能」ではなく、校正という普通の機能の実装手段** —
だからリボンに AI タブは作らず、レビュー > 校正 に置く。

- 宛先は 127.0.0.1 のローカルサーバ(OpenAI互換 `/v1/chat/completions`)。
  **基幹網は外に出ない**ので、閲覧の分離設計と矛盾しない。
  `JO_PROOF_HOST` / `JO_PROOF_PORT` / `JO_PROOF_MODEL` で差し替え
- Command A+ はオープンウェイト(migration-kit DESIGN.md でローカルAIとして採用済み)。
  ただし大型なので相応の GPU メモリが要る(同 DESIGN.md の注記)
- **モデルの作り話は通さない**: `found` が本文に実在しない指摘は捨てる
- **サーバが居なければ「校正できません」と出す。** 黙って「指摘なし」にしない
  (利用者が「誤りが無い」と受け取ってしまうため)

## なぜこれを作るのか — 英語は解放された。日本語は解放されなかった

英語の綴り検査は**公共財になっている**。この機械で確かめた:

    hunspell-en-us は システムパッケージ。
    依存元: libenchant-2-2, task-gnome-desktop, task-kde-desktop,
            task-xfce-desktop, task-mate-desktop, task-lxqt-desktop …
    語彙: SCOWL(Kevin Atkinson)・Moby lexicon・Princeton WordNet

**誰も英語を正しく綴るために Microsoft に金を払っていない。** 辞書は誰でも同梱できる。

日本語には対応物が無い。`/usr/share/hunspell/` に ja は無く、`apt-cache search hunspell`
にも日本語の辞書は出てこない。だから日本語の校正は、Word の校正・ATOK・Just Right! を
買うしかなく、いまそれがクラウド(Copilot)へ移りつつある。

**これは誰かの怠慢ではなく、構造。**

| | 誤りの正体 | 辞書で解けるか |
|---|---|---|
| 英語 | 綴り誤りは**辞書に無い語**になる (`recieve`) | 解ける → 公共財になった |
| 日本語 | 誤変換は**辞書に有る語**になる (「以外」/「意外」) | 解けない → 企業のものであり続けた |

ふりがなも同じ。「後」の読みは辞書に書けない(文脈で変わる)。
実測: 青空文庫5作・ルビ14,994箇所で、**読みが割れる語が561種**。

**オープンウェイトのモデルは、日本語にとっての hunspell になれる。**
hunspell が英語にしたこと(誰でも同梱できる・金を払わない・手元で動く)を、
日本語でやる。それがこのソフトの存在理由であり、
**言語の正しさの土台を一社から借りている状態を終わらせる**ということ。

## 辞書は答えではなく絞り込み(2026-08-02 に測り直した)

「英語は辞書で足りる」は**不正確だった**。辞書が答えられるのは
「この語は一覧にあるか」までで、**無い語が誤りかどうかは答えられない**。

    『高慢と偏見』 123,688語 → 辞書に無い語 312種 (0.25%)
    AMDの技術文書   2,114語 → 辞書に無い語  74種 (3.50%)

    例: Bennet, Bingley, Bakewell, Annesley … / DeepSeek, Docker, Franka, LangChain …

**全部、正しい語。** 辞書だけだと『高慢と偏見』に2,251件の「綴り誤り」を報告する。

だから配置はこうなる。**辞書は前置きの濾過器**で、残った未知語だけモデルに訊く
(固有名詞か、誤りか)。組み込みの固有名詞リストは誤魔化しなので、判定に置き換えた。

    英語  : 辞書が 99.7% を落とす → 0.25% だけがモデルに届く
    日本語: 辞書が何も落とせない  → 100%  がモデルに届く

**これが「日本語にGPUが要る」の定量的な意味**であり、同時に推論の最適化でもある
(一番速い推論は、動かさない推論)。同じ処理の流れで、濾過器の効きだけが違う。

判定の規則: **迷ったら name。** 正しい語を「誤り」と言う害の方が、
誤りを見逃す害より大きい。判定できなければ「綴り誤り」ではなく**未知語**として出し、
判定できなかったことを `skipped` に残す。一度判定した語は覚えて二度訊かない。

## 校正は office の一部。別ブランドで配らない

hunspell が英語で勝ったのは**誰でも同梱できたから**だが、それを可能にしたのは
**免許**であって、別売りのパッケージではない。だからこちらは
**aiseed office(仮称)として配り、校正はその中の機能**にする。
別ブランドの製品を増やさない。

**AGPL なので、単体で切り出して配りたい人は配れる。** こちらがやる必要はない。

`office-spell` と `furigana-bench` は残すが、これは**製品ではなく道具**である。
理由は1つで、**画面を開かずに回せないと測れない**から —
青空文庫17,000作品の命中率も、Radeon 上の推論速度も、窓越しには測れない。

    office-spell 文書.txt        指摘を出す(標準入力も可)
    office-spell -l              語だけ(hunspell -l と同じ形)
    office-spell --washi         第1候補を振った本文を pywashi の記法で出す

終了コードで区別する — **0=指摘なし 1=指摘あり 2=入力が読めない 3=検査できなかった部分がある**。
3 が要るのは、モデルが居ないときに 0 を返すと
「終了コード0 = 問題なし」と受け取られるため。**黙って「指摘なし」にしない**を
コードの形で守る(`Report::may_say_clean()`)。

固有名詞は一般の英語辞書に載らない(実際に `Radeon` → `Radon` と直された)。
hunspell と同じくユーザ辞書 `OFFICE_DICT_USER` で受ける。

## 表オブジェクトと右横書き — 方針変更(2026-08-04 発注者)

**改訂: 表オブジェクトは「持たない」から「持つ」へ。** 範囲に変換・
サイズ変更は表そのものが無いと成り立たない(名前の付いた範囲を外す・
広げる、という仕草)。`sheet::model::TableDef`(名前・範囲・見出し/合計/
縞々/最初/最後/フィルタ)を持ち、`xl/tables/tableN.xml` + worksheet の
tableParts + rels + Content_Types と往復する。**見た目は書式のまま** —
表を外しても帯や縞々は残る(Excel と同じ。「書式は据え置き」の掟にも合う)。
表を減らしたときは部品も宣言も消す(残すと Excel が「壊れている」と言う)。

**改訂: 右から左を「日本の事務では使わない」と言わない。**
日本語も右から書くことがある(右横書き — 昔の看板・横額・のれん)。
- **シートの方向**(`Sheet.rtl` ↔ sheetView rightToLeft): 列を右から
  並べる。実装は `visible_cols()` を逆順にする一点だけ — 描画も当たり
  判定もこの関数を通るので、見える場所と掴む場所がずれようがない
- **文字の向き**(`CellFormat.rtl_text` ↔ alignment readingOrder="2"):
  セルの中を1字ずつ右から並べる。**日本語の右横書きのための実装**で、
  ラテン文字の bidi(双方向)は扱わない — そう言って出す

## 日本語一級(K4)— 均等割付・ルビ・縦書き(2026-08-04 発注者「やってみて」)

紙面が**1字=1セル(x_mm 持ち)**なのが効いた — 3つとも「セルの置き方」の
話に落ちる。描画側は置かれた座標のとおりに出すだけ。

- **均等割付** = `Align::Distribute`。docx の `w:jc distribute` と往復
  (いままで両端揃えに丸めていた)。行の余りを字間に等配し、**最後の行も
  配る**(両端揃えとの違い)。描画は「同じ書式の連なりを1本で描く」を
  **x が飛んだら切る**よう改良 — 画面・PDF とも座標が正
- **ルビ** = `CharFormat.ruby: Option<String>`。field と同じ場所に持つ —
  run の切り貼り(分割で降ろす・同型は合流)の道具立てがそのまま効く。
  組版は基底の上(行送りの黄金比の余白の中)に**半分の大きさの行**
  (from_body=false)を置く。狭ければ中付きで等配、広ければ中央から
  はみ出す(基底を広げる詰めは残件)。docx は `w:ruby`(rubyPr/rt/
  rubyBase)と往復。基底が行で割れると読みが両方に付く(残件)。
  UI はホームの「ルビ」ボタン → パネルで読みを打って Enter(空で外す)
- **縦書き**(実装済み 2026-08-04): docx は sectPr の
  `w:textDirection w:val="tbRl"` と往復。組みは**変換方式** —
  行長 = 紙の縦の使い幅で普通に(横に)組み、できた行を
  「行 k → 右から k 本目の列」へ写す(fold_columns と同じ考え方)。
  Line.y_mm に列の x、Cell.x_mm に上からの距離を持たせ、Sheet に
  vertical の旗 — 描く側(画面・PDF)は旗を見て1字ずつ置く。
  約物は写すときに縦用の字形(、→︑ 。→︒ ー→縦棒 「」→﹁﹂ など)へ
  置換。ASCII の横倒しは初版ではしない(1字ずつ縦に積む)と正直に言う。
  クリック・キャレット・選択の当たり判定も旗で転置済み(キャレットは
  横棒)。実装は Line を変えず Sheet に vert_x(行ごとの列の x)を持たせた
  — 全指定 literal を割らない。ホームの「テキスト方向」で入切。
  初版の約束(status でも言う): 表・段組みは縦にならない、ASCII は
  1字ずつ縦に積む(横倒しはまだ)、変換下線は出ない、
  明示の改ページは列送りに畳まれる。LibreOffice が開けることを実地確認済み



Linux 前提で作ってきたが、**Mac 版も作る**。同じ writer / calc の移植なので
「新しいバイナリは作らない」の掟には触れない。ソースで裏を取った現状:

- **自作コード(engine / ooxml / sheet / lang / paper / ui / writer / calc)に
  OS の分岐は一つも無い**(`cfg(target_os)` 不使用)。素の Rust
- フォント探索(`engine/src/font.rs`)は最初から `/Library/Fonts`・
  `/System/Library/Fonts`・`~/Library/Fonts` を見る。ttc も読めるので
  ヒラギノはそのまま拾える見込み
- GPUI は Zed の母国が Mac(Metal)。GPU 描画・IME はむしろ本場。
  rfd のダイアログもネイティブに出る。排他ロック(`.~lock.名前#`)は
  ただのファイル操作でそのまま動く。`.linklibs/` の回避策
  (libxkbcommon-x11)は Linux 固有で、Mac では不要
- **唯一の本物の穴はサンドボックス。** bubblewrap は Linux 専用で、calc は
  `/usr/bin/bwrap` を直に見ている。いまのまま Mac で組むと、`@名前`
  (ブック搭載コード)と `=PY`/`@計算` は「サンドボックスがありません」で**正しく
  拒否される**(未移植でも嘘はつかず、安全側に落ちる)。一行コードと
  .py 選択実行は動く(深層防御が効かないだけ)

方針: Mac のサンドボックスは Seatbelt(`sandbox-exec`)で**同じ4条件**を組む —
網の遮断・実ファイルは読み取り専用・ホームは不可視・書けるのは交換用の
一時領域だけ。`@名前 net` の段階制(許可は毎回の明示の操作、ブックには
保存されない)もそのまま。実装はサンドボックスの組み立てを1箇所に集め、bwrap と
sandbox-exec を裏で差し替える形にして、4条件は両 OS 共通のテストで
突き合わせる。sandbox-exec は Apple が非推奨と言い続けているが現行
macOS で動く — 使えなくなったらそのときに考える。**サンドボックスが組めない環境では
今までどおり実行を拒否する**(黙ってサンドボックスなしに落とすことはしない)。
