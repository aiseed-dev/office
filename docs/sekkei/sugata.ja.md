## リボン(2026-08-02)

タブ名と並びは **Euro-Office に合わせる**(乗り換える人が場所を覚え直さずに済む)。
名前は vendor/web-apps の日本語ロケール ja.json から取った。定義は `ui/src/ribbon.rs`。

- writer: ファイル / ホーム / 挿入 / 描画 / レイアウト / 参考資料 / フォーム /
  共同編集 / 保護 / 表示 / プラグイン
  (**2026-08-04 改訂**: デスクトップ版に合わせ、ヘッダー・フッタータブは
  挿入へ、レビュータブは共同編集(変更履歴)と下のステータスバー
  (スペル・文字数)へ畳んだ。「コラボレーション」はデスクトップ版の
  呼び名「共同編集」に改名。**writer は 114/114 で灰色ゼロ** —
  詳しくは「writer の灰色ゼロ」の節)
- calc: ファイル / ホーム / 挿入 / 描画 / レイアウト / 数式 / データ /
  ピボットテーブル / 表のデザイン / コラボレーション / 保護 / 表示 / プラグイン
  (全タブ入り済み 2026-08-04。フォーム/ピボットテーブル/表のデザインは灰色置き、
  例外は表のデザインの「重複データを削除」= データタブと同じ実体、そして
  「ピボットテーブルの挿入」= polars 裏方で動く(発注者確定 2026-08-04)。
  結果はその時の値で右に置く — 開く=再計算の仕掛けは持たず、帳面には
  値だけが残る。同日、タブの残り(更新・すべて更新・選択・総計・小計・
  空行・レイアウト)も実装 — 指図(PivotDef)を独自部品 xl/joPivot.xml で
  ブックに控え、どのボタンも「指図を直して polars で置き直す」だけ。
  総計・小計は polars が元データから計算し直すので平均でも正しい。
  Excel で保存し直すと指図は消え、ただの値になる(正直な劣化))

**改訂(2026-08-04 発注者確定): メニューは制限せず全部入れる。**
共同編集・保護・プラグイン(マクロ含む)のタブも、場所は本家どおり並べる —
乗り換える人の目当てを消さない。**実装するかは別の判断**で、当面は灰色
(「できないものを、できるように見せない」は ready で守る)。
VBA 型マクロを実装しない方針は不変(コードの持ち運びは Python in Calc が
サンドボックスつきで担う)。

**再改訂(2026-08-04 同日・発注者「灰色のままにしない」)**: その
共同編集・保護・プラグインも**全部実装した**(writer)。共同編集モードは
排他ロックの顔、チャットは隣の .chat.txt、バージョン履歴は .jo-history、
保護は documentProtection、暗号化は ECMA-376(いまは Agile/AES-256)、
署名は隣の .sig、マクロとプラグインは**サンドボックスの中の Python + python-docx**。
**「相談事項として残る」は解消済み。** マクロが VBA でないことだけは
不変 — 文書の中に実行コードを置かない設計は守ったまま実現した。

**できないものを、できるように見せない。** 実装済みだけ押せる形にし、未実装は灰色で残す。
並びは Euro-Office のまま、進み具合(実装済み N/M)が画面に出る。
テストで `ready` と実体の食い違いを止めている。

## テーマ色(2026-08-04 発注者「テーマ色の読みもやりましょう」)

今どきの Excel はセルの色を **rgb で直に**書くほかに、
**テーマの何番目 + 明るさの加減(tint)**で書く(`<color theme="4" tint="0.4"/>`)。
読めないとその色が画面から消えるので読む。`sheet::theme`:

- `theme1.xml` の clrScheme を12色に読む。**番号の並びは Excel の流儀**
  (0=背景1(lt1) 1=文字1(dk1) 2=背景2 3=文字2 4〜9=アクセント)—
  部品の中の並び(dk1,lt1,…)とは逆なので読むときに入れ替える
- tint は HSL の明度だけを動かす(ECMA-376 の式)
- **由来も覚える**(`CellFormat.color_theme` / `fill_theme`)。だから
  **配色の変更**で色の組を入れ替えると、テーマ色を使うセルの色が追従する。
  書き出しも由来のまま(`theme=` / `tint=`)返す — 直の rgb に潰さない
- 配色は Office / 暖色 / 寒色 / 墨 の4組。テーマ部品は原文を持ち越さず
  モデルから書き直す(持ち越すと配色の変更が効かない)
- **インターフェイステーマ**(画面の明暗)は別物 — 額縁だけ暗くし、
  **セルは白のまま**(writer の「紙は白のまま」と同じ、画面と紙の一致)

## 画面の額縁 — デスクトップ版に合わせる(2026-08-04 発注者)

発注者がデスクトップ版 ONLYOFFICE の画面を示して「これに合わせて」。
writer で実施(calc への写しは申し送り):

- **1段目 = クイックアクセス+文書名**。保存・印刷・戻す・やり直しの
  アイコンを左に、中央に文書名(未保存は * 印)。この行が窓の取っ手
- **2段目 = タブ**。白地に文字、現在地は青い下線(タブ形の色分けを廃止)。
  右端に 🔍(検索と置換のパネル)
- **下端 = ステータスバー**。ページ n/m・文字数(生きた値)・状態の文言・
  スペル・ズーム −/%/＋。レビュータブのスペルと文字カウントの引っ越し先
- **タブの構成もデスクトップ版のとおり**: 「コラボレーション」は
  デスクトップ版の呼び名「共同編集」に(変更履歴もそこへ)。
  ヘッダー/フッタータブは畳んで挿入タブへ、レビュータブは畳んで
  共同編集とステータスバーへ。フォームタブは残す(発注者の
  「メニューを制限せず全部入れる」の確定を優先。デスクトップ版は
  docx では出さないが、うちは灰色=未実装の正直表示として残す)
- **ホームタブは本家の形**(2026-08-04 発注者が画像で指定): 2段組・
  絵だけのボタン・群の区切り線・フォント名と大きさはコンボ風(今の値を

- **挿入タブは一段**(2026-08-04 発注者が画像で指定): 主要なボタン

  足りない絵(表・画像・図形・SmartArt・グラフ2種・テキストボックス・

- **残りのタブも一段**(2026-08-04 発注者「残りのタブもやって」。並びは

- **ファイルタブは全面のページ**(2026-08-04 発注者が画像で指定):

  詳細設定・ヘルプ・機能のリクエストは灰色)、右に「文書の情報」=

  原本の他の欄は残し、こちらの5欄だけ置き直す。空にすれば消える)。

- **表示タブも本家の2段**(2026-08-04 発注者が画像で指摘「できていないものが

## 設定 — 器と言語(2026-08-04 発注者「きちんと動くように」)

いまの「設定」は環境変数(OFFICE_FONT・OFFICE_HOST 系・JO_PYTHON・
OFFICE_DICT_USER)が散らばっているだけで**器が無い**。言語はリボンが
ビルド時生成(gen_ribbon.py)なので利用者が切り替えられない。直す:

- **器**: `~/.config/office/settings.toml`(recent・sign.key の隣)。
  起動時に読み、**ファイルタブの「詳細設定」ページ**(本家と同じ場所)で
  編集して即保存。環境変数は**一時上書きの口**として残す
  (優先順: 環境変数 > settings.toml > 既定 — 現場の検証で差し替えたい
  ときのため)。writer と calc で1つのファイルを共有(節で分ける)
- **吸収する設定**: 言語 / 既定フォント / 校正の宛先(host・port・model・
  鍵・timeout)/ ユーザー辞書 / Python の径路 / 名乗り(ロック・チャット・
  署名に出る user@host — 現場では氏名にしたい)/ バージョン履歴の世代数 /
  インターフェイステーマ(いま灰色のボタンがこれで実体を得る)
- **言語は段階で、正直に**:
  1. 器と詳細設定ページ(まず設定が「在る」状態に)
  2. **リボンの言葉の実行時切り替え** — gen_ribbon の出力を
     「ロケール→表」の埋め込みへ変え、settings の language で選ぶ。
     元データは vendor/web-apps のロケール(45言語。**元の機械でないと
     再生成できない制約**に注意 — 表の生成はあの機械でやる)
  3. 状態行・パネル・右クリックの文言の外部化(lang クレートへ。数百句 —
     一番大きい。済むまでは「リボンは選んだ言語・**状態行は日本語**」と
     詳細設定ページに正直に書く)
- **方針との整合**: 言語の選択肢には**文言が揃った言語だけ**を出す
  (最初は ja。en が2番手)。「45言語対応」を名乗るのは表が揃ってから —
  できないものを、できるように見せない

## 罫線は「場所×ペン」の直交モデル(2026-08-08 発注者確定)

「罫線で Microsoft 方式はやめて」— Excel の罫線▼にある「太い下罫線」
「下二重罫線」「太い外枠」のような**太さ・線種を型に焼き込んだスタンプは
持たない**。持つのは直交した2つだけ:

- **場所**(どの辺か): 下・上・左・右・外枠・格子・内側の縦・内側の横・消す
  の9種をパレットの絵で選ぶ
- **ペン**(何で引くか): 線種13種(細・中太・太・破線・二重…)と色。
  太い外枠が欲しければペンを中太にして外枠、二重の下線が欲しければ
  ペンを二重にして下罫線 — 覚えることは1つ

パレットの絵はペンの太さ・二重をそのまま映す(色も追従)。
帳票の枠は「細で格子 → ペンを中太で外枠」の連打で組む(パレットは
掛けても閉じない)。

## キーの嘘 — 束縛と受け口は別(2026-08-08 蒸留の検分で発覚)

`ui/src/lib.rs` の KeyBinding は **calc と writer で共有**している。
束縛があっても、そのアプリに `on_action` の登録が無ければ**押しても何も
起きない**。これで手引きに嘘が2件入っていた(Ctrl+F/H の検索・置換、
Shift+Tab の左移動 — どちらも受け口を持つのは writer だけ)。

- **束縛の存在を「効く」の証拠にしない。** 証拠は各アプリの
  `on_action(cx.listener(...))` の並び(calc は view.rs の末尾)
- リボンの ready の嘘は wiring_tests が落とすが、**キーの嘘を落とす試験は
  まだ無い**(在庫。ui の Action 一覧 × 各アプリの on_action 登録を
  突き合わせて、束縛だけあって受け口が無い物を挙げる形が素直)
- 直したいのは文書ではなく実装の側 — 消したキーは「効かない」と正直に
  書くのが当座で、本筋は受け口を足すこと(calc の Ctrl+F は 🔍 のパネルを
  開くだけで足りる)
