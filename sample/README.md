# sample — 公開できるサンプル

「開いて・直して・刷る」を試すための帳票と文書。**中身はすべて架空**
(実在の様式・人名・社名は入っていない)。templates/ が「ブック=業務アプリ」の
見本なのに対し、こちらはただの普通の書類。

```bash
./target/release/calc  sample/見積書.xlsx
./target/release/writer sample/報告書.docx
```

## calc 用(xlsx)

- **見積書.xlsx** — 結合(表題)・罫線・表示形式(¥#,##0)・式(数量×単価、
  SUM・ROUND)・印刷範囲(A4 縦)。数量や単価を打ち直すと合計まで
  再計算される。ファイル > 印刷で PDF にすると印刷範囲どおりに出る
- **出納帳.xlsx** — 前行を引き継ぐ残高の式・条件付き書式(残高が1万円を
  割ると塗って知らせる — 最終行で実際に発動している)・セルのコメント・
  タイトル行の繰り返し
- **成績表.xlsx** — AVERAGE・MAX・COUNTIF(">=80")と条件付き書式
  (80点以上を塗る)

## writer 用(docx)

- **報告書.docx** — 見出しの階層・表・本文。参考資料 > 目次 を押せば
  見出しから目次ができる
- **送付状.docx** — 右揃え(日付・差出・敬具)と中央揃え(表題・記)の定型
- **議事録.docx** — 見出し+表(開催情報)+決定事項

## writer の見どころ(sample/writer/)

**日本語一級とうちだけの機能**を実際に使った見本。docx なので Word でも
LibreOffice でも開ける(4件とも実際に開けることを確認済み)。
生成器は Rust の例 — python-docx では素直に書けないもの(ルビ・縦書き・
記入欄・均等割付)を含むため:

```bash
cargo run -p ooxml --example gen_writer_samples   # sample/writer/*.docx を作り直す
./target/release/writer sample/writer/01_日本語の組版.docx
```

- **01_日本語の組版.docx** — ルビ(組版・禁則処理)、均等割付(項目名を
  端から端まで)、ドロップキャップ、箇条書き、英文のハイフネーション、
  コメント。レイアウト > 列の挿入 で2段に組み直せる
- **02_縦書きの手紙.docx** — 縦書き(右の列から左へ)。句読点とかぎ括弧が
  縦用の形になり、ルビも縦で振れる。ホーム > テキスト方向 で横書きへ戻せる
- **03_申込書.docx** — 表+記入欄(コンテンツコントロール)。氏名・メール・
  電話・ドロップダウン(参加する回)・チェック(☐☑)・署名。欄は薄い箱で
  見え、中は普通に打てる。保護タブの「保護」で読み取り専用にして配れる
- **04_月次報告.docx** — 見出しの階層・ヘッダー・フッターのページ番号・
  表・段落の帯・コメント・しおり(相互参照の的)。参考資料 > 目次 で
  ページ番号つきの目次ができる
- **05_道具くらべ.docx** — 釦を順に押して試すための紙。書式の見本行・
  しおり・図表番号・コメント・表が1枚に入っている。
  **この5件は試験の材料でもある** — writer の試験
  (`cargo test -p writer menu_run`)が5件すべてを開いて、
  リボンの釦を全部おし、落ちないこと・未配線が無いことを確かめる

## 注文書付きカタログ(writer 用・サーバー連携の見本)

- **カタログ.docx** — 分類ごとの見出し+商品表(36品目)、巻末に注文書の
  ページ。writer で開いて 参考資料 > 目次 を押せば、ページ番号つきの
  目次ができる
- **商品マスタの正本はサーバー、docx は生成物**という分業の見本:

```bash
python3 sample/catalog_server.py           # マスタを配る(127.0.0.1:8765)
.venv/bin/python sample/gen_catalog.py     # サーバーから取って作り直す
```

サーバー側は価格改定と新商品(37品目)を持っているので、作り直すと
カタログが追従する。**繋がらなければ、そう言ってから**同梱の見本データで
作る(黙って古いままにしない)。追跡に入っているのは同梱データ版。

### Web でも配る(JS なしの HTML)

同じサーバーが同じ商品マスタから **JS なしの HTML** も出す(1ソース多形態):

- `GET /catalog.html` — カタログ。**商品はカードで陳列** — 絵(サーバーが
  SVG を生成。ボールペンはインクの色まで見える)・品名・値段が一目。
  検索(`?q=テープ`)、分類の開閉(details/summary)、札を選んで
  **「選んだ商品を比べる」** → サーバーが比較表を組み、いちばん安い列に
  印を付ける。どれも実行コードなしの「動き」の見本
- `GET /compare?c=A-101&c=…` — 比較表(上の form の行き先)
- `GET /img/品番.svg` — 商品の絵。**実物では販売者が用意した画像
  (写真等)を置いて配るだけ** — この見本では画像ファイルが無くても
  動くよう、代役の絵をその場で生成している
- `GET /order.html` — 注文書のフォーム。**記入して「注文を送る」だけ** —
  form の POST は JavaScript 以前からの素の仕組みで、JS は一切無い
- `POST /order` — フォームからも、注文書.xlsx の @送信 net(JSON)からも受ける。
  偽の品番の行は受けず、どの行を受けなかったかを言う

writer の HTML 読み(SEKKEI「JS なしの閲覧と記入」)が入るまでは、普通の
ブラウザが仮の閲覧手段。入ったらこの2ページがそのまま検証相手になる。
サーバーの Python は管理者が別途配る — 文書と一緒に旅をしない。

- **注文書.xlsx** — カタログの受け側(calc 用)。品番を打つと品名・単価が
  右の H〜J 列(品番マスタの写し)から VLOOKUP で引かれ、金額・小計・
  消費税・合計まで式で埋まる。品番の欄には入力規則(候補はマスタの写し)。
  ブックにコードが2本載っていて(データ > Python の板):
  - `@更新 net` — マスタの写しをサーバーの正本と入れ替える(価格改定・
    新商品に追従し、金額は再計算される)
  - `@送信 net` — 品番と数量の入った行を JSON でサーバーへ送る
    (受付番号が返る)

  開いただけでは何も実行されない。実行は毎回の明示の操作で、必ず檻
  (bubblewrap)の中 — net の許可もその場で打ったときだけ。式の入った
  行を増やすときは既存の行を Ctrl+C → Ctrl+V で写す。

## e-shop の試作 — Word で店を書く(eshop.py)

「販売者が Word で店を書き、プラグインが店を開く」の一本道の実証
(SEKKEI「e-shop」の節。本実装は writer のプラグインになる予定):

```bash
.venv/bin/python sample/eshop.py        # カタログ.docx → 商品マスタ.csv
python3 sample/catalog_server.py        # 店が開く(CSV があれば自動で読む)
```

- **店の正本は文書。** 品を足す・値を直すのは writer(または Word)で
  カタログ.docx を直し、上の2つを回し直すだけ — Web の知識は要らない。
  分類は見出し、商品は表(品番/品名/説明/単価)から取る。記入欄など
  商品表でない表は飛ばす
- 商品マスタ.csv は生成物なので追跡しない(正本は文書)
- 注文は店の /orders に溜まる — 下の**受注台帳.xlsx**が引き取る

## 受注台帳.xlsx — 販売管理(calc 用)

e-shop の受け側の帳面。**空で出荷**され(台帳は記録 — 見本の記録は
持たない)、店に溜まった注文を引き取って行を刻む:

- データ > Python で **`@取り込み net`** — 新しい注文だけを追記する
  (取込済の件数を K2 に控えるので、何度押しても重複しない)。
  品名・単価は**その時のマスタの値**で刻む(台帳は記録なので式で
  引き直さない)。金額は式(数量×単価)、右上に売上合計(=SUM)
- **発送済**の列はチェックボックス(空白キーで ☑/☐)
- 売上の集計は calc の既存道具がそのまま効く: **ピボットテーブル**
  (社名別・品番別の売上)、**小計**、**並べ替え・絞り込み**
- 開いただけでは何も実行されない。実行は毎回の明示の操作+檻の中

## writer の HTML 読みの受入サンプル(html/)

writer の「HTML — JS なしの閲覧と記入」を実装するときの受入試験の材料。
1ファイル=1つの焦点で、**ページ自身が合格の条件を本文で語る**。
一覧と根拠は [html/README.md](html/README.md) に。
(01 文書の基本 / 02 表と癒し / 03 箇条書き / 04 絵と網の線引き /
05 記入欄 / 06 POST の往復 / 07 ページの Python / 08 JS の読み飛ばし /
09 未知タグ / 90 文字コードの正直な拒否)

## 作り直し

サンプルは生成物。直すのは生成側で、ファイルを直接直さない。

```bash
cargo run -p sheet --example gen_samples   # xlsx 4件
.venv/bin/python sample/gen_docs.py        # docx 3件(要 python-docx)
.venv/bin/python sample/gen_catalog.py     # カタログ.docx
```

どれも検査つき: xlsx は pysheet で開いて式の値を、docx は
`ooxml --example rtall` で往復(本文一致・注記0)を確かめてある。
